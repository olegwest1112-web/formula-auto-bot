# Formula Auto

Telegram Mini App автосалону Formula (Нововолинськ). Публічний каталог, заявки менеджеру та закрита панель власника.

- Каталог: https://olegwest1112-web.github.io/formula-auto-bot/
- Панель: https://formula-auto-nv-mini.olegwest1112.chatgpt.site/admin
- Тестовий бот: https://t.me/formulatestastrabot
- Тестовий канал: https://t.me/formulatestttt

## Для власника

Увійдіть у панель через ChatGPT обліковим записом власника. У порожній базі натисніть «Завантажити початкові 4 авто з каналу» — один раз. Далі каталог редагується в панелі, без зміни коду.

«Додати авто»: заповніть характеристики, завантажте до 24 JPG/PNG/WebP (8 МБ кожне), розташуйте фотографії стрілками. Перше фото — обкладинка. Увімкніть «Показувати в каталозі» та оберіть наявність. Чернетки, приховані та архівні авто не відображаються покупцям. Архів можна відновити як чернетку. Внутрішні примітки не передаються в публічний каталог. Одночасне редагування у двох вкладках захищено перевіркою версії.

Заявки: нова → у роботі → закрита. Якщо сповіщення Telegram не доставлено, заявка залишається в базі; є повторне надсилання. У панелі відображаються останні 500 заявок. Історія містить останні 100 адміністративних змін. Експорт JSON зберігає інвентар з внутрішніми примітками — зберігайте його приватно.

Контакти та тестовий режим змінюються в налаштуваннях. Тестові заявки також реально зберігаються й надсилаються призначеному тестовому менеджеру. Перед реальним запуском перевірте актуальність автомобілів, фото, цін, телефону і контактів. Права бота на реальний канал видає його адміністратор; отримувач повідомлень має почати діалог із ботом.

## Архітектура

`dist/` — статичний клієнт на GitHub Pages. Він читає актуальну базу через API, без підміни застарілим локальним каталогом при відмові сервера. `backend/` — ESM Worker, D1 база, R2 фото. `admin/` — панель на тому ж домені сервера. Вхід — платформний Sign in with ChatGPT; сервер перевіряє `ADMIN_EMAILS` у кожному адміністративному запиті. Довірені заголовки автентифікації встановлює платформа, не клієнт.

GitHub Actions перевіряє код, публікує клієнт і оновлює існуючий пост у каналі. Сервер розгортається через Sites окремо: одного push у GitHub недостатньо для зміни сервера. Вихідний код обох частин зберігається тут. GitHub Pages не виконує серверний код.

### Змінні середовища

GitHub Actions secret: `TELEGRAM_BOT_TOKEN`; variable: `TELEGRAM_POST_ID` (поточний пост 2).

Сервер: `ADMIN_EMAILS` (дозволені власники), секрети `TELEGRAM_BOT_TOKEN`, `MANAGER_CHAT_ID` (числовий chat ID) і `RATE_LIMIT_SALT`. Токени ніколи не додаються у файли чи клієнт. Зміна username в контактах не переналаштовує секретний числовий chat ID.

### Локальна розробка

Node.js 24. `npm ci`, `npm test`, `npm run check`, `npm run build`. `npm run db:generate` генерує міграції зі `db/schema.ts`. Застосовані міграції не редагувати. Збірка сервера — `build/server/index.js` плюс `build/.openai/`; при пакуванні для Sites цей каталог нормалізується в `dist/` архіву. Публічний `dist/` GitHub залишається окремим.

Тести перевіряють права, CSRF, публікацію/архів, конфлікт версій, настройки, валідацію, повторну відправку, обмеження частоти та CORS. Нові заявки мають ключ повторної відправки; персональні дані зберігаються тільки на сервері та у повідомленні менеджера. Секрети й персональні дані не записуються в журнал змін.
